# 章画面の節まわりの操作モデル 再設計

- 日付: 2026-09-15
- 対象: 章表示画面（読書モード）の節の行・節コメントの印・節コメントシート・節詳細画面
- 関連: #65（スワイプ）、#161（押下時間の測り方）、#162（プレビューの遅延マウント）

## 背景

章画面の 1 つの面に、7 つの入力が積み上がっている。

| 操作 | 結果 |
|---|---|
| 節の行をタップ | 節詳細へ遷移（`?verses=[n]`）|
| 節の右の印をタップ | 非モーダルの下シートでその節のコメント |
| 印を 400ms 以上押す | シートは開かず、投稿が対象にしている節の範囲だけ塗る |
| 横スワイプ | 前後の章へ移動 |
| ヘッダーのアバター | 投稿者で絞り込み |
| FAB | 章へ投稿 / 節を選んで投稿 |
| 選択モード中の行タップ | 選択のトグル |

問題は 2 つある。

**1. 同じ行の中でタップ先によって結果が違う。** 行の本文をタップすると画面が遷移し、行の右端の印をタップすると背面を保ったままシートが開く。どちらも「その節について知りたい」という同じ意図から出る操作なのに、行き先も、章の文脈を失うかどうかも違う。

**2. 押下時間で結果が変わる。** 印には 400ms の長押しゲートがあり、越えるとタップが無効になる。これは「シートを開かずに範囲だけ見る」ための設計だが、24px の的を狙うとき指は普通にそれくらい留まる。実際に「タップしても選択されない」という報告が出た。

調査の結果、押下時間の測り方にも欠陥があった（詳細は #161）。ハンドラが呼ばれた時刻で測っていたため、触れた直後の描画で主スレッドが詰まると、その詰まりが押下時間に足される。計測では次のようになる。

```
測られる押下時間 ≒ max(実際に押していた時間, 触れた直後の描画時間)
```

つまり 400ms を越えるのは「描画が単体で 400ms かかる」か「本当に 400ms 以上押している」かのどちらか。前者は描画コストを消す #162 で潰れる。後者は設計そのものの問題で、閾値をいじっても消えない。24px の的を狙って 400ms 押すのはごく普通の操作であり、報告された症状の説明として残るのはこちらである。

もう 1 つ、構造上の重複がある。「その節への投稿」を見せる面が 2 つある。

| | 節詳細画面（`?verses=[n]`）| 節コメントシート |
|---|---|---|
| 入口 | 節の行タップ | 印タップ |
| 中身 | 公式サイトリンク・節本文・その節への投稿一覧・投稿ボタン | その節に関わる投稿一覧 |
| 章の文脈 | 失う | 保つ |
| 共有 | URL になる | ならない |

## 決めたこと

章画面は**読むことと書くことが同等**に扱われる面とする。その上で、

- 読書モードのタップ先は**行だけ**にする。1 行 1 ターゲット、1 結果
- 行タップは**その節のシートを開く**（`?comment=n`）
- 印は**非対話の目印**に降格する。長押しゲートは廃止する
- 節コメントシートを「その節の面」に育て、節詳細画面は**直リンク専用**にする
- 行全体がタップ対象になるとテキスト選択が塞がるため、**シートにコピーボタンを置く**

### 検討して採らなかった案

| 案 | 内容 | 不採用の理由 |
|---|---|---|
| 行タップ＝何もしない | シートを開くのは印だけ | コメント 0 件の節に触れる手段が無くなり、書く導線が FAB 経由だけになる。「読むと書くが同等」と噛み合わない |
| 行タップ＝節の選択（モードレス）| 行タップで選択、下部にアクションバー。選択モードを丸ごと廃止できる | 構造は最も単純になるが、読んでいる最中に触れるたび選択が走る。読書側のコストが高い |
| 長押しの閾値を 400→500ms に上げる | iOS / Android の慣習に揃える | 症状を薄めるだけで、行と印で結果が違う問題は残る |

## 変更後の操作モデル

| 操作 | 変更後 | 差分 |
|---|---|---|
| 節の行をタップ | その節のシートを開く（`?comment=n`）| 節詳細への遷移をやめる |
| 節の右の印 | 目印だけ。押せない | ボタンをやめる。長押しゲートも消える |
| 横スワイプ | 前後の章へ | 変更なし |
| ヘッダーのアバター | 投稿者で絞り込み | 変更なし |
| FAB | 章へ投稿 / 節を選んで投稿 | 変更なし |
| 選択モード中の行タップ | 選択のトグル | 変更なし |

**失うもの**: 「シートを開かずに範囲だけ見る」長押し。ただしシート内の投稿カードに触れると対象節が塗られる挙動は既にあるため、範囲を知る手段そのものは残る。

## 節コメントシート

非モーダルのまま（背面の章はスクロールでき、別の節をタップすれば中身が差し替わる）。

```
┌─ 第1ニーファイ書 1:3 ───────── [×] ┐
│ 3 わたしニーファイは善い両親から…      │  ← 節本文（併記中は英文も）
│                                      │
│ [コピー]  [公式サイトで読む →]        │
│ ────────────────────────────────── │
│ この節に関わる投稿 2件                │
│ ┌──────────────────────────────┐   │
│ │ 👤 アリス  …                   │   │  ← 触れると対象節が塗られる（既存）
│ └──────────────────────────────┘   │
│ [ この節に投稿する ]                  │
└──────────────────────────────────┘
```

- **節本文を出す**。シートは下 7 割を覆うため、タップした節（＝指のある位置＝下寄り）は背面で隠れやすい
- **コピー**。`参照 + 改行 + 本文` をプレーンテキストで。参照は既存の `getScriptureLabel` が返す形。例:
  ```
  第1ニーファイ書 1:3
  わたしニーファイは善い両親から生まれたので、…
  ```
- **公式サイトで読む**。節詳細から移設（`buildScriptureUrl` が既にある）
- **この節に投稿する**。コメント 0 件の節でも書き始められる。投稿シートはモーダルなので、節シートを閉じてから開く（履歴も 1 段で済む）

### コピー本文の作り方

`scripture_verses.text`（プレーン）は取りに行かない。章のロードで全節ぶんのプレーンテキストまで運ぶのは、読む側のコストが割に合わないため。`text_html` から作る。

`<rt>` と `<rp>` を除いてから `textContent` を取る。除かずに `textContent` を取ると、ルビが「漢字かんじ」と二重に出る。`innerHTML` ではなく `DOMParser` で解析する。

## アクセシビリティ

- 節の行は `Link` から `button` へ。読み上げ上の名前は節本文のまま（今も `Link` が本文を包んでいるのでパリティ）。`aria-haspopup="dialog"` を付ける
- 印は `aria-hidden` の飾りにする。代わりに「コメント N 件」を視覚的に隠したテキストとしてボタンの中に入れ、件数の情報は読み上げに残す

## スコープ外

- 選択モードの再設計（モードレス化）。FAB → 節を選んで投稿、は今のまま
- 印の見た目そのものの変更
- 節詳細画面の中身の整理（本文と投稿一覧が残る形のまま）
- 章コメンター行（ヘッダーのアバター）の変更

## 出す順序

**実施後の記録（2026-09-16）**: 下記のとおり 2 本に分けて出す想定だったが、最終レビューで挙がった修正が前半・後半の両方のファイルにまたがったため、**1 本の PR にまとめた**。分けると前半だけ修正の欠けた状態になるのを避けた。順序そのもの（シートを育ててから行タップを切り替える）は計画どおり守っている。


1. **節シートを「節の面」に育てる** — 本文・コピー・公式サイトリンク・「この節に投稿する」を追加。入口は今の印のまま。単体で価値があり、既存の挙動を壊さない
2. **行タップの割り当て変更と印の降格** — 行を `button` にして `?comment=n` を開き、印を非対話にする。長押しと塗りの所有権コードがここで消える

1 だけ入った状態でも画面は成立する。2 が大きいのでレビューを分ける。

### 先行している PR の扱い

- **#162（プレビューの遅延マウント）はマージする。** この再設計と独立で、縦スクロールのたびの無駄な描画を消す。残り続ける価値がある
- **#161（押下時間をイベント時刻で測る）は close した。** `VerseCommentGutter.tsx` を削除すると、押下時間を測るコード自体が無くなる。加えて、あの修正が効くのは「描画が単体で 400ms を越える」場合だけで、実機でそこまで遅くなるとは考えにくい。報告された症状には効かない見込みのため、止血としても採らない

## テスト

| 対象 | 固定すること |
|---|---|
| `verseHtmlToPlainText` | ルビが二重にならない。`<rp>` も落ちる。タグ無しの本文はそのまま |
| `VerseRow`（読書）| タップで `onOpen(verse)` が呼ばれる。遷移しない。「コメント N 件」が読み上げに乗る |
| `VerseCommentMarker` | 押せる要素を描画しない |
| `VerseCommentSheet` | 節本文が出る。コピーで参照＋本文がクリップボードに入る。0 件でも「この節に投稿する」が出る |
| 章ページ | コメント 0 件の節をタップしてもシートが開く。`?comment=n` の直リンクが任意の節で開く |

既存の `VerseCommentGutter.test.tsx` は 35 件中 10 件ほどが長押しと塗り所有権のテスト。印の降格とあわせてまとめて削除する。

## 実機で見る項目

- 読んでいる最中の誤タップでシートが開く頻度が許せる範囲か（机上では決められない）
- 行がボタンになってもスワイプが効くか
- コピーが iOS のホーム画面 PWA で通るか（`navigator.clipboard` は secure context 必須。本番は https なので通る見込み）

## 互換性

- `?comment=n` は「コメントのある節」限定から「章の範囲内の任意の節」へ広がるだけなので、共有済みの URL は壊れない
- `?verses=` の節詳細は残す。投稿詳細（`pages/posts/$id.tsx`）からその聖典参照へ飛ぶ導線が使っている
