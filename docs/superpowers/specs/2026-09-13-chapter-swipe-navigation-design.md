# 章画面のスワイプナビゲーション 設計（再設計）

- 日付: 2026-09-13
- 対象 issue: #65
- 前身: `docs/superpowers/specs/2026-07-25-chapter-swipe-navigation-design.md`（`worktree-chapter-swipe-navigation` ブランチ。ポインタイベント自前実装。実機で左スワイプが直らず放置）

## 背景

旧実装はポインタイベントを自前で処理し、7つの fix コミットを重ねても iOS 実機の左スワイプが直らなかった。原因は個別のバグというより、**ジェスチャの所有権を React がブラウザと奪い合ったこと**にある。縦横の方向ロック、節リンクのクリック抑止、ポインタキャプチャ、マルチタッチ——いずれもブラウザが標準で持つ挙動を再実装していた。

本設計では横方向のスクロールコンテナ（CSS scroll-snap）を使い、ジェスチャの処理をブラウザに戻す。

## スコープ

- 対象: `$chapter.tsx` の `ChapterView`（章全体表示）。`VerseView` は対象外
- 左スワイプ = 次の章 / 右スワイプ = 前の章（issue 本文の記載は古い。旧実装の実機検証で入れ替えた向きを踏襲する）
- 移動先の計算は `getAdjacentChapterRef`（#151 で main 済み）をそのまま使う。書の境界またぎ・前付け文書のスキップ・コレクション境界での `null` は実装・テスト済み
- #151 の前章・次章リンク（`ChapterNav`）は残す。スワイプは近道で、リンクがキーボード／スクリーンリーダー向けの正規の導線

## 構造

```
features/swipe-chapter-navigation/
  lib/useChapterPager.ts   -- スクロール位置の監視・着地判定・進捗
  ui/ChapterPager.tsx      -- 3パネルの横スクロールコンテナ + 行先ラベル
  index.ts
```

### パネル構成

```
[ 前の章（空パネル） ][ 章の本文 ][ 次の章（空パネル） ]
```

- 各パネルは `min-width: 100%`。スナップ地点を全て到達可能にするため、両脇も本文と同じ幅にする
- 移動先がない方向（コレクション端）のパネルは描画しない
- コンテナ: `display:flex; overflow-x:auto; scroll-snap-type: x mandatory; overscroll-behavior-x: contain`、スクロールバーは既存の `no-scrollbar` で隠す
- 両脇のパネルは空にし、行先は `position: fixed` のラベルとして画面中央に重ねる。パネル内に置くと、章の高さぶん縦に伸びたパネルの上端にラベルが行ってしまい、下の方を読んでいるときに見えない

### 初期位置

`scrollLeft` を中央パネルの先頭に合わせる。CSS だけでは中央から開始できないため `useLayoutEffect` で設定する（描画前に済むのでちらつかない）。`useIsMobile` は SSR と初回描画で `false` を返すので、両脇のパネルはマウント後にしか現れない。SSR 時点では中央パネルだけが存在し `scrollLeft` は 0 のままでよい。

### 着地の検知

`scroll` イベントを rAF で間引いて拾い、最後のイベントから 120ms 動きがなければ着地とみなす。

- `Math.round(scrollLeft / clientWidth)` でどのパネルに着地したかを求める
- 両脇のパネルに着地していれば `navigate` する
- `scrollend` は Safari の対応状況が環境依存なので使わない。`IntersectionObserver` も使わない（jsdom で検証できず、着地位置の計算より間接的）

遷移後はルートが変わり、`ChapterPager` は章参照を `key` にしているので再マウントされ、中央から始まる。

### 無効化

`disabled` のときはコンテナを `overflow-x: hidden` にしてスクロール自体を止め、着地判定も行わない。**パネルの描画は止めない**——描画を切り替えると本文の DOM が作り直され、読んでいた縦位置を失う。

無効化する条件:

- `mode === 'select'`（節選択モード）
- `VerseCommentSheet` / `PostComposerSheet` が開いている間（非モーダルなシートの背面でスワイプできてしまうのを防ぐ）
- `useIsMobile`（<1024px）が false、または `(pointer: coarse)` でない
  - 日英併記の2カラムは `lg`（≥1024px）なので、この条件で競合しない
  - `(pointer: coarse)` を見るのは、狭くしたデスクトップウィンドウでトラックパッドの横スクロールが章移動に化けるのを防ぐため

## 前回の fix コミットが潰そうとした問題との対応

| 旧実装で自前に書いたもの | 本設計 |
|---|---|
| 縦スクロールとの方向ロック（`preventDefault` のタイミング） | ブラウザのスクロール方向ロック |
| 節 `<Link>` の誤タップ抑止 | パン後はブラウザがクリックを発火しない |
| ポインタキャプチャ / window リスナーの付け外し | 不要 |
| マルチタッチ乗っ取り対策 | 不要 |
| 指追従のアニメーションと 20% のしきい値 | ブラウザのスクロールとスナップ |

引き換えに「何割引いたら移動するか」はブラウザのスナップ判断に委ねることになり、自前では決められない。読書中の章送りという用途では実害が小さいと判断した。

## 既存要素との競合

| 要素 | 判断 |
|---|---|
| `VerseCommentGutter` の長押し | 対処不要。横パンに移ると `pointercancel` が飛び、ガター側は既に処理済み |
| `VerseCommentSheet`（非モーダル）| 開いている間は無効化する |
| 日英併記の2カラム | `lg` 以上でのみ2カラム。有効化条件（<1024px）で競合しない |
| 節リンク | 対処不要。ブラウザがパン後のクリックを抑止する |
| #151 の前章・次章リンク | 併存させる |
| `content-visibility: auto`（`verse-item`）| 影響なし。`checkVisibility({ contentVisibilityAuto: true })` で数えた描画スキップ数も、ページ全体の高さも main と同じだった（アルマ書5章・62節で確認）|

## 既知の制限

- iOS Safari の通常タブでは画面端からの右スワイプが履歴の「戻る」に奪われる。ホーム画面 PWA（standalone）では発生しない想定だが、実機で確認する
- スクロールコンテナに入ることで `scrollIntoView`（印から節へ移動する処理）の挙動が変わらないか確認する

## テスト

`tests/features/swipe-chapter-navigation/ChapterPager.test.tsx`（jsdom には実レイアウトがないため、`clientWidth` と `scrollLeft` はテスト側で差し込む）:

- 両隣があるとき、前後のパネルを描画する
- コレクション端では該当方向のパネルを描画しない
- マウント時に `scrollLeft` が中央パネルに合う
- 隣のパネルに着地して静止すると、その章へ `navigate` する
- 中央で静止しても `navigate` しない
- `disabled` のとき、パネルは残したままスクロールを止め、着地しても `navigate` しない
- デスクトップ（`useIsMobile` が false）ではパネルを描画しない

**実機検証は実装の途中に置く。** 前回はここで詰まった。コンテナと空パネルだけができた時点で一度 iOS ホーム画面 PWA と Android Chrome で触り、進捗ラベルなどの仕上げはその後にする。ローカル検証の手順は `.claude/skills/verify/SKILL.md`。

## 追補（2026-09-14）: 移動先の先読みとプレビュー

引いている間に移動先の章の本文が見えるようにした。

### 先読み

`ChapterPager` がマウント後のアイドル時（`requestIdleCallback`、上限2秒）に、両隣の章を
`router.preloadRoute` でルートごと先読みする。節本文だけを別に引くと、指を離した後の遷移で
同じものをもう一度取ることになるため、**loader の結果をそのままプレビューに使う**。

- `preloadRoute` が返すのは読み込み前の写しで `loaderData` を持たない。読み込み済みの実体は
  `router.getMatch(id)` 側にある
- 章ルートに `preloadStaleTime: 60秒` / `preloadGcTime: 30分` を設定した。既定の
  `defaultPreloadStaleTime` は 0 で、先読みしたそばから古い扱いになり取り直しになる
- 併記の英文は loader が取らないので、そこだけ React Query で別に引く（`staleTime: Infinity`）
- 先読みするのはモバイル＋粗いポインタのときだけ。デスクトップでは通信しない

### プレビューの置き方

パネルは章の高さぶん縦に伸びるため、中身をそのまま入れると章の先頭に置かれ、下の方を
読んでいるときに画面の外へ出る。指が触れた時点で縦位置を1回測り、パネル内の絶対配置で
画面1つぶんだけ描く（横ドラッグ中は方向ロックで縦に動かないので、1回の計測で足りる）。

**下げ幅はスクロール量そのもの**にする。そうするとプレビューはコンテナの先頭、つまり章の
本文が始まる位置に重なる。遷移した先も本文はそこから始まるので、ヘッダーやその下に何が
どれだけ積まれているかを知らなくても縦位置が揃う。

貼り付いているヘッダーの高さを測って下げる形にすると、ログイン時だけ出る投稿者アバターの
行（`ChapterCommentersRow`。ページャの外にある）を数え落とし、読み進めた位置でスワイプ
したときに本文が33px跳ねる。

節のマークアップは `renderPreview` でページ側から渡し、本体と同じ `VerseRow` を使う。
**外側の余白・区切り線・節の組みも `verseList` と同一にする**（`p-4` の外枠、
`flex items-stretch` の行、最終節だけ区切り線なし）。ここがずれると、指を離した瞬間に
本文が横や縦に飛ぶ。章名の見出しはプレビューに置かない。本体では章名はヘッダーにあり、
本文の側に置くと節の位置がその高さぶんずれる。

先頭40節までしか描かない（それ以上は画面に入らない）。プレビューを出せない方向
（先読みが間に合っていない、通信が失敗した）は、これまでどおり行先ラベルを出す。

### 残っている差

移動先に「この章への投稿」の一覧や節の印（ガター）が出る場合、プレビューはそれらを描かない。
どちらも先読みした loader のデータには含まれているので閉じられるが、プレビューの
マウントは指が触れた瞬間なので、投稿カードまで描くと重くなる。

### 検証（タッチをエミュレートした Chrome）

| 確認項目 | 結果 |
|---|---|
| 左に引くと次の章の本文が見える | 通過 |
| プレビューが出ている方向では行先ラベルを出さない | 通過 |
| 読み進めた位置でもプレビューが画面内にある | 通過 |
| 遷移直後に本文を取り直していない | 通過 |
| 直前に見た章へ戻るとき、節本文を取り直さない | 通過 |
| プレビューと遷移後で、本文の左余白・幅・上端が一致する | 通過（19px / 358px / 73px で同値）|
| 投稿者アバターの行が出る状態でも上端が一致する | 通過（スクロール0 / 1500px のどちらでも 106px）|
| プレビューに見えていた本文が、そのまま遷移後の先頭になる | 通過 |


## 追補（2026-09-14, 2）: キャッシュ層の一本化（Codex レビュー反映）

先に入れた「`router.preloadRoute` で章ルートごと先読みし、`getMatch()` から節本文を取り出す」形は
以下の問題があり、作り直した。

- 本文プレビューのためだけに、投稿・認証・身内情報まで先読みしていた
- `preloadStaleTime` は**先読みの鮮度判定にしか使われない**。通常の遷移はルートの `staleTime`
  （このルートは未設定＝0）で判断されるため、「遷移で取り直さない」という当初の意図は成立して
  いなかった。実測でも遷移のたびに `_serverFn` が2本飛んでいた
- `preloadRoute()` の戻り値は loader データを持たず、`getMatch(id)` と型アサーションで
  引き直していた。loader の戻り値を変えてもコンパイルで気づけない

### 直した形

`entities/scripture/lib/verseTextsQuery.ts` に**キーと queryOptions を1つだけ**置き、
ページ本体・SSR のローダー・隣章の先読みがすべてそれを使う。

| 使う側 | 呼び方 |
|---|---|
| SSR のローダー | `context.queryClient.ensureQueryData(scriptureVerseTextsQuery(ref, 'ja'))` |
| 章画面・節画面 | `useQuery(scriptureVerseTextsQuery(...))`（第1・第2言語とも） |
| 隣章の先読み | 同じ options を `useQueries` で4本（前後 × 言語）|

- 節本文はサーバー関数の戻り値から外した。ローダーが取るのは投稿・認証・身内情報だけ
- クエリのクライアントは、ブラウザでは既存の共有クライアント、サーバーでは cookie を持たない
  匿名クライアント。節本文は RLS で anon にも SELECT が開いている公開データなので、
  セッションは要らない
- ルートの `preloadStaleTime` / `preloadGcTime` は削除した
- 先読みの有効条件を `interactive` から `scrollable` に変えた。節選択モードやシート表示中は
  スワイプを譲っているので、先読みも止める

### 計測（タッチをエミュレートした Chrome）

| | 旧（preloadRoute）| 新（Query 一本化）|
|---|---|---|
| 章を開いたときの先読み | `_serverFn` ×2（投稿・認証込み）| 節本文クエリ ×2（本文のみ）|
| 遷移時の通信 | `_serverFn` ×2（**移動先の本文を取り直し**）| `_serverFn` ×1（投稿・認証）＋次の隣章の先読み ×1 |
| 指を離してから URL が変わるまで | 552ms | 541ms |
| SSR に本文が入るか | 入る（ruby 728個）| 入る（ruby 728個）|

遷移時に移動先の節本文を取り直さなくなった。ルート先読みをやめた分の遅延は計測できる差が
出ていない（この時間はスナップのアニメーションと着地判定が大半を占める）。
